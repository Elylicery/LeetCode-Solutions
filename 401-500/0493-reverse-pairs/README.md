# 493. 翻转对

## 思路：归并排序，参考 [LCR 170. 交易逆序对的总数](https://github.com/Elylicery/LeetCode-Solutions/blob/main/LCR/0170-shu-zu-zhong-de-ni-xu-dui-lcof/README.md) 的归并思路

两题都是「递归把左右两半排好 → 统计跨区配对 → 合并」，区别在于统计能不能塞进 merge 里：

* LCR 170 数 `arr[i] > arr[j]`，条件就是归并时的比较条件，所以取走 `aux[j]` 时左半剩下的 `mid - i + 1` 个全部构成逆序对，**合并即计数**，一趟完成。
* 本题数 `arr[i] > 2 * arr[j]`，而 merge 按 `arr[j]` 本身排序，两者错位，取走 `aux[j]` 时左半只有一部分满足条件，`mid - i + 1` 会算多。
* 所以拆成两步：**先数后合并**（`countReversePairs` + `merge`）。
* 先数的依据：左右两半各自已升序，右半整体乘 2 后仍然升序（乘 2 单调，负数同样成立），于是对固定的 `arr[i]`，满足 `arr[i] > 2 * arr[j]` 的 `j` 是右半的一个**前缀**；`i` 递增时该前缀只增不减，`j` 指针不回退 → 一趟线性扫描，`count += j - (mid + 1)`。
* 循环条件用严格 `>`：`arr[i] == 2 * arr[j]` 不算翻转对。
* 必须先数再合并：合并完左右混在一起，`mid` 的分界信息消失，跨区配对无从统计。

时间复杂度：O(n log n)
空间复杂度：O(n)（辅助数组 aux 在入口分配一次，逐层复用；每层 merge 只复制 `[l, r]` 区间）
是否修改原数组：是
